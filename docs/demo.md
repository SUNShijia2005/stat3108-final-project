# Parcel Desk 当前演示与回归检查

启动 `python3 app.py`，打开 http://127.0.0.1:8765。此次演示以寄件准备为终点，不实际下单或提交海关文件。

## 0. 先确认聊天模式

当前本机已接通 Gemini 3.1 Flash-Lite，并通过一条开放问题的真实对话测试。密钥仅保存在被 Git 忽略的本机配置。未配置密钥的其他安装仍会显示「尚未连接 AI 模型」。

点击「启用 AI 对话」，填写服务商提供的模型名称和 API Key；如使用兼容接口，展开「模型服务地址与接口格式」，填写 HTTPS 地址并选择 Responses 或 Chat Completions。点「保存并启用」后无需重启。此按钮只保存设置，不发起付费测试；实际发消息时才请求所填服务。密钥只保存在本机项目的 `.env.local`，不放进浏览器存储或任务记录。更换服务地址时需要重新填写该服务的密钥。

配置后可试这组连续对话：

> 我今天有点累，不想聊寄件。
>
> 帮我用两句话解释过拟合。
>
> 再用一个生活中的例子说说。

预期是直接回应当前话题，并使用前文理解追问，而不是反复列出寄件功能或附加“本轮没有修改已保存需求”。当前接口和路由用模拟响应测试过；这组开放对话的实际质量仍需在接通模型后检查。每次请求最多带入24条近期消息、18,000字符历史及必要的寄件摘要；聊天中输入的文本会发送到所选模型服务。

## 1. 建立需求

点击「体验示例任务」。系统新建独立示例任务，路线为上海至洛杉矶90001，棉质T恤10kg，30×20×10cm，预算5,000 CNY。联系人及地址为虚构占位信息；物流示例没有被自动当作这票货的轨迹。

在对话中输入：

> 如果改成8kg会便宜多少？先不要修改我的10kg需求。

应显示独立试算及费用差额，右侧保存重量仍为10kg，已有报价、单证检查和参考方案不被试算覆盖。再输入「把重量改成8kg」，此时保存重量才变成8kg，并显示实际修改摘要。

## 2. 比较并选择参考服务

进入「比较参考方案」。10kg示例的参考小计为IE 3,879.30、IP 3,950.30、IPE 4,151.30 CNY；明确改为8kg后为IE 3,167.30、IP 3,226.30、IPE 3,383.30 CNY。这些小计包含基础运费及来源版本入境处理费，尚有燃油等待核验项目。

可将尺寸改为50×40×30cm，保存并重新估算；体积重12kg高于8kg实重，因此按12kg计算，IE参考小计为4,267.30 CNY。修改尚未保存时，下方旧结果应有提示，不能选择旧方案。

点击任一「选择此参考方案」进入文件核对。选定的是准备时使用的参考服务；时效、覆盖和最终费用仍需承运人核验。再次修改计费相关需求后，原选择应失效，需要重新估算和选择。

## 3. 保存草稿并核对文件

进入「核对寄件文件」，修改寄件人姓名，暂不保存。去「查询物流」展开独立官方示例并点击查看，再返回文件页，刚才的姓名应保留。刷新或切换到另一任务后再返回，同一任务的草稿也应恢复（浏览器存储可用时）。状态必须标明这是尚未保存到任务的本机草稿。

把装箱数量从2改成1，点击「保存并检查」。页面应在相应货品行标出发票与装箱数量不一致，点击结果可以定位字段。恢复2，再把合计从50改成60，检查金额冲突；恢复50后通过基础一致性检查。

如从空白任务开始，使用「带入当前货品描述」，再填写真实数量、价格和原产地。不会自动猜测数量或单价。预览商业发票和装箱单，核对当前已保存的重量、尺寸及货品；预览为可打印HTML，可通过新标签中的打印功能保存PDF。

## 4. 查看准备清单

进入「寄件准备清单」。确认显示已保存路线、参考服务及小计、文件检查状态和向承运人核验的事项。未完成步骤应清楚显示缺项；全部准备步骤通过也不应显示已经寄件或承运人已接受货物。

点击「打印／保存准备清单」查看打印预览。本页或包裹页仍有未保存草稿时，应要求先处理草稿，避免输出旧信息。

## 5. 查询物流、找回任务

物流页要求实际运单号和明确勾选Ship24查询。没有真实号码时使用折叠区内的「查看官方物流示例」；它是四个法国事件的缓存，与当前中国至美国任务无关联，也不消耗新包裹额度。聊天泛泛询问物流不应直接替换成这个示例结果。

点击「新建寄件任务」，再用左侧历史选择器找回刚才的示例。任务名称应能辨认路线、货品和重量；各任务草稿分开保存。

## 6. 查看技术检查

展开侧栏「项目与评估」，查看最近一次生成的Python测试结果及18条检索问题。准确的状态、总数和逐项结果以 `results/evaluation.json` 为准。JavaScript草稿逻辑另有17项检查：

```bash
python3 scripts/evaluate.py
node tests/drafts.test.cjs
```

这些是组件和固定开发问题的结果。线上模型比较与真实客户运单验证尚未完成。只有明确配置模型后，对话才可能消费该模型服务的额度。
